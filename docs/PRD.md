# Ruby 技术博客 PRD

版本：1.0 · 2026-10-27 · 产品负责人：Ruby Liang · 状态：持续维护

本文件定义**要为谁解决什么问题、交付哪些体验以及如何验收**。详细数据模型、API、安全和检索约束见 [PRODUCT.md](PRODUCT.md)；工程规则见 [ENGINEERING.md](ENGINEERING.md)；任务依赖与实际完成情况见 [PLAN.md](PLAN.md)。当本文件与旧文档的范围或当前状态冲突时，以本文件和最新用户决定为准；实现细节的变更需同步相关规范。

## 1. 背景与目标

Ruby 的代码笔记和课程笔记需要一个可公开、可持续整理的入口。网站既帮助读者理解技术问题，也作为 Full-stack / Applied AI 求职作品，展示 Ruby 如何分析问题、做技术取舍、实现方案和复盘踩坑。

核心内容只有三类：

1. **技术博客**：问题背景、调查过程、实现与验证、踩坑及复盘。
2. **课程笔记**：按主题组织的系列文章，有目录与前后篇导航。
3. **关于我**：公开简介、技术方向和 Ruby 明确选择公开的链接。

关键词搜索和基于已发布文章的引用式问答是阅读入口，不是独立内容栏目。

## 4. P1：可阅读的 mock 内容站点

### 4.1 内容与发布状态

- 定义 Article、Series、Profile 的公共契约与 ContentRepository；mock 和未来 API provider 使用相同的已验证 DTO。
- 准备至少 8 篇完整、可合法公开的样例：4 篇技术博客，以及两个课程系列各 2 章；另有不公开的草稿、中文英文混合、长代码和缺图等边界样例。
- 文章明确区分 draft、published、archived。草稿不能进入公开页面、搜索索引、sitemap 或 API；样例不得自动导入私人笔记、简历隐私或雇主代码。
- 文章保留稳定 slug、语言、标题、摘要、标签、发布日期和更新时间。系列按显式顺序组织章节。

### 4.2 技术博客

- `/blog/` 提供文章标题、摘要、标签、日期及可分享的筛选/分页状态；无匹配内容时显示明确空状态。
- `/blog/[slug]/` 提供安全渲染的正文、目录、代码高亮与复制、图片 alt、更新时间和返回入口。
- 每篇已发布文章有可直接访问的 HTML、独立 title/description/canonical；失效 slug 返回真实 404。
- 文章结构应让读者看到**问题 → 调查/取舍 → 实现/验证 → 踩坑复盘**，但不强迫每篇使用同一模板。

### 4.3 课程笔记

- `/notes/` 列出系列；`/notes/[seriesSlug]/` 展示系列介绍和有序章节；章节页显示目录与前后篇。
- 导航只包含已发布章节；第一篇没有上一篇，最后一篇没有下一篇；删除或重排后不能产生断链或循环。

### 4.4 关于我

- `/about/` 提供公开简介、技术方向和经 Ruby 确认的外链；首页简介可作为摘要。
- 不从简历自动发布电话、私人邮箱、住址或其他未明确选择公开的信息。

### 4.5 关键词搜索

- 初期使用构建生成的本地索引，覆盖已发布文章；支持中英文及 JWT、EF Core、C++ 等精确技术词。
- 结果含标题、匹配摘要、内容类型和可访问链接；有清除输入、无结果、键盘操作与可分享筛选状态。

### 4.6 P1 完成标准

所有公开路由可直接打开及刷新；文章/章节导航可用；草稿不泄漏；桌面和手机端可读；320 CSS px 不出现意外横向滚动；主要路径通过格式、lint、类型、单元与浏览器验收。静态构建不需要运行时 Next.js 服务。sitemap/RSS、metadata、404 和 GitHub Pages 子路径均验证。具体边界测试以 [PRODUCT.md](PRODUCT.md) 与 [PLAN.md](PLAN.md) 为准。

## 5. P2：真实内容和媒体

- NestJS + Fastify 内容服务以 MongoDB 为 canonical store，负责文章、系列、公开简介、媒体元数据和发布状态。Web 通过 ContentRepository 切换至真实 provider，真实模式失败不得悄悄退回 mock。
- Ruby 专用管理流程支持草稿编辑、发布/撤回、版本冲突、权限校验和可追踪、可重试的构建触发。正式身份供应商仍待决定。
- 图片由 AWS S3 保存，受限上传、格式/尺寸校验与处理后的公开变体分发；CloudFront/OAC 方案和付费资源须在预算与权限确定后实施。
- 发布与撤回必须同时考虑静态页面重建、搜索/AI 索引和缓存；删除数据库记录不能视为公开内容已撤回。

P2 的真实云集成需要单独验收。离线替身通过不代表 MongoDB Atlas、S3、认证或部署已上线。

## 6. P3：文章检索问答

- 使用 Python + FastAPI。先实现可靠的文章索引、检索、引用校验和回答流程；仅在需求与评估证明必要时考虑 Agent 编排框架。
- `/ask/` 支持单轮问题、内容类型/系列过滤、回答、来源卡片、取消、重试及错误状态。问答只依据**当前已发布**的文章与章节。
- 证据不足时明确返回 `insufficient_evidence`；模型超时、错误或限流时不能伪造答案。引用只能指向本次检索到且仍有效的文章版本与锚点。
- 正文与检索结果是非可信数据，不能执行其中的指令或代码。模型和数据库密钥不进入浏览器。
- 正式发布前至少有 40 题评估集，并达到 [PRODUCT.md 第 7 节](PRODUCT.md)规定的检索、引用、支持度、拒答与草稿隔离门槛；不能把 mock 演示当作真实问答。

## 7. 非功能要求与技术边界

- 默认英文导航，文章可中文或英文；无需强制逐篇双语翻译。
- 清晰、安静的蓝色阅读视觉；语义 HTML、可见焦点、键盘导航、减少动画偏好，目标 WCAG 2.2 AA。自动扫描不是完整人工无障碍验收。
- 关键静态页面以受控环境 Lighthouse 性能分数 ≥ 90 为目标；记录设备/网络条件，不把单次分数当作真实用户指标。
- Web 使用 Next.js 静态导出并部署 GitHub Pages。Pages 不能提供 SSR、ISR、Server Actions 或运行中的 Next API；后端服务需单独部署。
- 保持 TypeScript strict、锁定依赖、Husky hooks、PR 审核与必需 CI。技术架构和依赖方向见 [ENGINEERING.md](ENGINEERING.md) 与 ADR。

## 8. 不做什么与待决事项

不做留言、支付、多租户、公开注册、社交动态、项目作品集、自治 Agent、联网搜索、Kubernetes、Kafka 或 GraphQL。当前没有预算和真实需求时不预建云资源。

待 Ruby 决定：哪些真实笔记可以公开、About 页公开的联系方式与链接、AWS 预算/region、管理员 OIDC、模型及 embedding 供应商、Atlas Search 配额与云网络方案。上述待决事项不阻塞 P1 本地 mock 工作。
